RIESGOS, DEL MÁS AL MENOS PROBABLE
1. Llave pública con acceso total: las páginas usan la llave anónima de Supabase (visible en el código de la página) y
   casi todas las tablas tienen reglas «for all to anon using (true)». El usuario y la clave del sistema controlan la
   pantalla, no la base: alguien con conocimientos técnicos podría leer, cambiar o borrar datos sin entrar al sistema.
2. Sin respaldos propios: el plan gratuito de Supabase no da respaldos descargables; el Pro guarda 7 días. Las imágenes
   (Storage) no entran en esos respaldos. Falta confirmar en qué plan está cada proyecto.
3. Error humano: un SQL en la base equivocada o un borrado (los SQL entregados se detienen si detectan otra base).
4. Cuentas: pago vencido, perder acceso al correo dueño, un solo dueño por servicio → proyecto pausado o sin acceso.
5. El repositorio no basta para recrear las bases: faltan los SQL antiguos (antes del 15A; por ejemplo 5A de insumos y
   9A de limpieza). Hace falta un respaldo de la estructura completa.
6. Cierre definitivo de Supabase o Netlify: muy poco probable y con aviso; con respaldos propios sería solo una mudanza.
